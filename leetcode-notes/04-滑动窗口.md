# 滑动窗口（Sliding Window）

> 专题笔记（路线图**阶段 3**）。来源：LeetCode 209（Minimum Size Subarray Sum）。
> 数据均为本机 Python 3.12 实测。

## 一、一句话本质

**窗口 = 一段连续的区间 `[left, right]`。右端点负责扩张，左端点按条件收缩。**

它是双指针的升级版：双指针只有「两个位置」，滑动窗口多了**一个窗口内的状态**（本题是元素和，后面还会遇到字符计数、频次表）。

两种形态：

| 形态 | 窗口长度 | 收缩判据 | 典型题 |
|---|---|---|---|
| **定长窗口** | `right - left + 1` 固定 = k | 超出 k 就丢左边 | 643、567 |
| **变长窗口** | 可变 | 满足/不满足某个条件就收缩 | **209**、3、424、76 |

## 二、209. Minimum Size Subarray Sum（第一题）

### 1. 题目要点

- 找「**和 ≥ target 的最短连续子数组**」，不存在就返回 **0**（不是 -1）；
- **Constraints 里 `1 <= nums[i]`（全为正数）是这题能用滑窗的根本原因**，见下面第 3 点。

### 2. 通用模板（背这个结构）

```python
left = 0
state = 初始状态            # 本题 state = 窗口内元素和
ans = 哨兵（float('inf') 之类）
for right in range(len(nums)):
    把 nums[right] 纳入 state
    while 需要收缩（本题：state >= target）:
        更新 ans
        把 nums[left] 移出 state
        left += 1
return ans if ans != 哨兵 else 0
```

209 的完整代码：

```python
left = 0
total = 0
result = float('inf')
for right in range(len(nums)):
    total += nums[right]
    while total >= target:
        result = min(result, right - left + 1)
        total -= nums[left]
        left += 1
return result if result != float('inf') else 0
```

### 3. 为什么「元素全为正数」才能这么写（这题最关键的一步）

滑窗成立的前提是：**窗口状态随右端点单调**。

- 全为正数 ⇒ 窗口越长，和越大 ⇒ **一旦 `total >= target`，再往右加只会更长，不可能更优** ⇒ 可以放心把 left 往右收缩；
- 如果允许**负数**，加一个数反而可能让和变小 ⇒ 「达标」不再意味着「可以收缩」，这套写法就失效了（这类题就得换武器，比如前缀和 + 哈希表）。

> 结论：**动手写滑窗前，先看 Constraints 里有没有「正整数」这类单调性保证。**

### 4. 复杂度

**O(n)**：`right` 走 n 步，`left` 总共也最多走 n 步 ⇒ 每个元素最多被「纳入一次、移出一次」。
空间 O(1)（只有几个变量）。

实测（n = 10⁵）：

| 版本 | 耗时 |
|---|---|
| 变长滑窗 O(n) | **4.655 ms** |
| 暴力 O(n²) | **31255 ms**（31 秒 → 必然 TLE） |

### 5. 暴力版（第一版，值得留着）

「固定 left，往后累加到达标就记录长度并 break」——写法正确，只是 O(n²)：

```python
for left in range(len(nums)):
    get = nums[left]
    if get >= target:
        result = 1
        break                    # 长度 1 已是最小可能值，不用再找
    else:
        for right in range(left + 1, len(nums), 1):
            get += nums[right]
            if get >= target:
                result = min(right - left + 1, result)
                break
```

### 6. 踩坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | 找不到答案返回 0 | 不是 -1，也不是哨兵本身 |
| 2 | 哨兵用 `float('inf')` 更稳 | 比 `-1` 或 `n+1` 更不容易和真实答案混淆 |
| 3 | 忘记「先更新答案再收缩」 | 顺序错了会漏掉「刚好达标那一瞬间」的长度 |
| 4 | 用滑窗却忽略了元素可能为负 | 前提不成立时结果会错，先查 Constraints |
| 5 | 内层 `while` 忘了移出 `nums[left]` | 和没减够 → 死循环 |
