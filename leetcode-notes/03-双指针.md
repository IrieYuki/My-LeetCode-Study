# 双指针（Two Pointers）

> 专题笔记（路线图**阶段 2**）。来源：LeetCode 167（Two Sum II）。
> 文中的耗时数据都是本机 Python 3.12 实测，不是估计值。

## 一、一句话本质

**用两个下标代替一层循环，把 O(n²) 压成 O(n)。**

它的成立条件通常是二者之一：

- **数组有序** → 两个元素的大小关系能告诉你「该动哪个指针」（167 / 11 / 15）；
- **可以原地读写** → 一个指针负责扫描、一个负责写回（26 / 283）。

## 二、167. Two Sum II - Input Array Is Sorted（第一题）

### 1. 解法：左右夹逼

```python
left, right = 0, len(numbers) - 1        # 一个指最小，一个指最大
while left < right:
    s = numbers[left] + numbers[right]
    if s == target:
        return [left + 1, right + 1]     # 题目要 1-indexed
    elif s < target:
        left += 1                        # 和太小 -> 左指针右移
    else:
        right -= 1                       # 和太大 -> 右指针左移
```

### 2. 为什么不会漏掉答案（双指针的证明套路）

| 情况 | 推理 | 结论 |
|---|---|---|
| `s < target` | 右端**已经是当前最大的数**，配上 `numbers[left]` 都不够大 | `numbers[left]` 可以**永久排除** → `left += 1` |
| `s > target` | 左端**已经是最小的数**，配上 `numbers[right]` 都太大 | `numbers[right]` 可以**永久排除** → `right -= 1` |

每一步都至少排除一个元素，两个指针加起来最多走 n 步 → **时间 O(n)**，只用了两个变量 → **空间 O(1)**。

> 记住这句证明模板：**「每次移动都永久排除一个候选，所以总步数有上界」** —— 后面 11、15、42 都靠它。

### 3. 和 1. Two Sum 的对比（同一道题的两种环境）

| | 1. Two Sum | 167. Two Sum II |
|---|---|---|
| 输入 | 无序 | **已排序** |
| 武器 | 哈希表 | 双指针 |
| 空间 | O(n) | **O(1)**（题目 Follow-up 的要求） |
| 返回下标 | 0-indexed | **1-indexed** ⚠️ |

**这两题合起来说明一件事：「有序」是能换钱的** —— 有序可以省掉哈希表那 O(n) 的空间，也可以省掉一层循环。

### 4. 踩坑

**坑 1：写了 O(n²) 的双层循环，完全没用上「有序」。** 实测（答案落在最右端的最坏情况）：

| n | 暴力双层 for | 双指针 |
|---|---|---|
| 1,000 | 10.17 ms | 0.037 ms |
| 3,000 | 91.66 ms | 0.094 ms |
| 10,000 | 973.06 ms | 0.310 ms |
| 3×10⁴（题目上限） | 约 9 s → **TLE** | **0.748 ms** |

→ **题目给了什么条件，就必须用上什么条件。** 数组有序 = 内层循环可以省。

**坑 2：在 `for` 里手动改循环变量。**

```python
for left in range(len(numbers)):
    ...
    left += 1        # ← 无效！下一轮会被 range 重新赋值
```

更糟的是它**污染返回值**：`return [left + 1, right + 1]` 用的是被改过的 `left`，
官方示例 2 `[2,3,4], target=6` 因此返回 `[2, 3]`（正确是 `[1, 3]`）。

→ **要手动移动指针，就必须用 `while`。** 这是所有双指针题的标准写法。

**坑 3：下标基准。** 167 要 1-indexed（`left + 1`），1. Two Sum 是 0-indexed。做题先看题目要哪种。

## 三、11. Container With Most Water（第二题）

### 1. 解法：夹逼 + 每次移动短板

```python
left, right = 0, len(height) - 1
best = 0
while left < right:
    best = max(best, min(height[left], height[right]) * (right - left))
    if height[left] < height[right]:
        left += 1            # 动短板：高度才有机会变高
    else:
        right -= 1
return best
```

### 2. 为什么必须移动短板

- 起点是「最左 + 最右」→ **宽度已经是全场最大**（`n-1`）；
- 之后每移动一次，宽度**必然 -1**（宽度只会走下坡）；
- 面积 = `min(左右两板高) × 宽度`，宽度只降 → 想变大**只能靠高度变高**：
  - 动**长板**：短板原地不动 → 高度被锁死 → 高度不升、宽度还降了 → **必然不更优**；
  - 动**短板**：高度有机会被更高的板顶上去 → 有可能更大。

实测（官方示例 `[1,8,6,2,5,4,8,3,7]`）：

```
起点:        宽 8, 高 min(1,7)=1  -> 面积 8
动长板(7→3): 宽 7, 高 min(1,3)=1  -> 面积 7    ← 变小，白费力气
动短板(1→8): 宽 7, 高 min(8,7)=7  -> 面积 49   ← 变大 ✓
```

### 3. 为什么不会漏解（= O(n) 的证明）

当 `height[left] < height[right]` 时，看**以 left 为左端点的所有容器**：

- 宽度最大只有当前这个值（再往右挪只会更窄）；
- 高度永远被 `height[left]` 锁死（短板在这里）。

→ 所以它们的面积**不可能超过当前已知的答案** → `left` 这个位置可以**永久排除**。

每步排除一个位置，两个指针一共最多走 n 步 → **时间 O(n)**，只用了 `best/left/right` → **空间 O(1)**。

### 4. 暴力 vs 双指针实测

| 方案 | 复杂度 | 实测 |
|---|---|---|
| 双指针 | O(n) | n=10⁵ → **5.21 ms** |
| 暴力枚举所有配对 | O(n²) | n=5000 → 482 ms（上限 10⁵ 时约 400 倍） |

## 四、15. 3Sum（第三题）

### 1. 思路：排序 + 固定一个数 + 双指针（降维）

```
排序 → 固定 nums[i] → 在 i+1..n-1 里找两数之和 = -nums[i]（167 的左右夹逼）
```

把「三个自由变量」压成「1 层循环 + 2 个指针」——**这就是降维**。3Sum 结构上只是 167 外面多套一层循环。

### 2. 解法

```python
nums.sort()
res = []
for i in range(len(nums) - 2):
    if i > 0 and nums[i] == nums[i - 1]:      # 去重关 1：外层
        continue
    l, r = i + 1, len(nums) - 1
    while l < r:
        s = nums[i] + nums[l] + nums[r]
        if s == 0:
            res.append([nums[i], nums[l], nums[r]])
            l += 1
            while l < r and nums[l] == nums[l - 1]:   # 去重关 2：左边
                l += 1
            r -= 1
            while l < r and nums[r] == nums[r + 1]:   # 去重关 3：右边
                r -= 1
        elif s > 0:
            r -= 1
        else:
            l += 1
return res
```

### 3. 三道去重关（这题唯一的难点）

| 关口 | 判据 | 为什么这么写 |
|---|---|---|
| 外层 `i` | `i > 0 and nums[i] == nums[i-1]` | 有序 ⇒ 重复值相邻；相同的 `i` 会产出同一批三元组 |
| 命中后左边 | `while l < r and nums[l] == nums[l-1]` | `l` 刚 +1，`nums[l-1]` 就是**刚用过**的值 |
| 命中后右边 | `while l < r and nums[r] == nums[r+1]` | `r` 刚 -1，`nums[r+1]` 就是刚用过的值 |

⚠️ 三个细节：

1. 判据是「**等于**前一个」才跳过（写反就变成跳掉所有不重复的）；
2. 比较对象是「**刚用过的位置**」（`l-1` / `r+1`），不是「下一个位置」；
3. `while` 里别忘 `l < r` 防越界；命中后**必须先移动指针**，否则死循环。

> 实测 `[-2,0,0,2,2]`：内层不跳过重复 → 得到 `[[-2,0,2], [-2,0,2]]`（同一组答案两次）。

### 4. 复杂度与实测

| 项 | 值 |
|---|---|
| 时间 | O(n²)（外层 n × 内层夹逼 O(n)）；题目 n ≤ 3000 |
| 空间 | O(1)（排序原地，不计输出） |
| 实测 n=3000 随机数 | 136.6 ms，16377 组解 |
| 实测 n=3000 全 0 | **0.108 ms**（去重把整个内层压成一步） |

### 5. 踩坑（这一题踩得最多，值得逐条看）

| # | 坑 | 实测 |
|---|---|---|
| 1 | `s = nums.sort()` | `list.sort()` 原地排序、**返回 None** → `s[i]` 报 `TypeError: 'NoneType' object is not subscriptable` |
| 2 | 去重条件写反 | `if i == 0 or nums[i] != nums[i-1]: continue` → 第一个数永远不参与，重复值反而没跳过 |
| 3 | **找到第一个解就 `return`** | 题目要【所有】三元组；实测只返回 `[-1,-1,2]`，漏掉 `[-1,0,1]` |
| 4 | 内层不跳过重复 | `[-2,0,0,2,2]` → 同一组答案出现两次 |
| 5 | 命中后不移动指针 | 条件完全相同的**死循环** |
| 6 | 变量名撞车 | `s` 既是排序结果又是三数之和，被覆盖成整数后 `s[...]` 会崩 |
| 7 | 内层手写一遍两数之和 | 命中后只需「移动 + 跳过重复」，搜索交回外层 `while` |

## 五、双指针的两种常见形态（本专题后面都会遇到）

| 形态 | 谁在动 | 适用 | 本专题题目 |
|---|---|---|---|
| **对撞指针** | left 从 0 向右、right 从 n-1 向左 | 数组**有序**，靠大小关系决定动谁 | 167、11、15、42 |
| **快慢 / 读写指针** | slow 指着「下一个要写入的位置」，fast 扫描 | 需要**原地**压缩数组 | 26、283 |

## 六、关键点 / 易错点

1. 双指针的价值是**省掉一层循环**：O(n²) → O(n)；代价是「必须先有序」或「必须能原地改」。
2. 「该动哪个指针」要有半句理由：动左边是因为**右边已经是最大的**，动右边是因为**左边已经是最小的**。
3. 手动移动指针 → 用 `while`；`for` 的循环变量改不动（会被 range 覆盖），而且会污染返回值。
4. 复杂度证明模板：**每步至少排除一个候选 → 总步数 ≤ n**。
5. 交卷前先确认下标基准（1-indexed / 0-indexed）。
6. **要返回「所有解」时，去重是主角**：先排序让重复值相邻，然后在**每一层**跳过重复（3Sum 一共三道关）。
7. 命中之后必须移动指针（两个都要动），否则条件不变 → 死循环。
6. **「该动哪个指针」的判断依据 = 谁在限制当前答案**：167 的限制来自两端的**和**，11 的限制来自**短板的高度** —— 限制答案的那一端才值得动。
