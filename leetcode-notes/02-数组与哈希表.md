# 数组 & 哈希表（Array & Hashing）

> 专题笔记（路线图阶段 1）。来源：LeetCode 49（Group Anagrams）。
> 本文里的耗时数据均为本机 Python 3.12 实测，不是估计值。

## 一、一句话本质

**用 `dict` / `set` 把「查一个东西在不在」从 O(n) 降到平均 O(1) —— 拿空间换时间。**

哈希表能成立的前提：key 必须**不可变（hashable）**、且「查询用的东西」和「存储用的 key」是同一个。

---

## 二、核心问题：怎么设计 key

哈希表题目的难点从来不是「用不用哈希表」，而是 **key 长什么样**。判断标准：

> 题目说「两个东西算同一类」时，它们**若真的同一类，算出来的 key 必须完全相等**；若不同类，key 必须不同。

49 题的推导过程（费曼式自问自答）：

| 问题 | 答案 |
|---|---|
| anagram 之间差什么？ | **只有字母顺序** |
| 那顺序是干扰项吗？ | 是 → 把顺序抹掉 |
| 怎么抹掉？ | 排序（`sorted`），或干脆不记录顺序（计数表） |
| key 用什么类型？ | `tuple(sorted(s))` / `tuple(计数表)`，**list 不能当 key** |

⚠️ **最容易错的判据**：以为「字母集合相同」就算 anagram。

```
"aab" 和 "abb" 的字母集合都是 {a, b} —— 但它们不是 anagram！
因为 a/b 的【出现次数】不同。
```

所以 key 必须同时包含「有哪些字母」和「各出现几次」。`set(s)` 单独用一定错。

## 三、两个实测踩坑

### 坑 1：多维护一个 `seen` 列表来记 key

```python
seen = []                       # ❌ 多余
for s in strs:
    key = tuple(sorted(s))
    if key in seen:             # list 线性查找
        d[key].append(s)
    else:
        seen.append(key)
        d[key] = [s]
```

| 写法 | 10⁴ 个词的实测耗时 |
|---|---|
| `if key in seen`（list 线性查） | **0.449 s** |
| `if key in d`（dict 哈希查） | **0.004 s** |

**121 倍**，而且 `seen` 是平方级增长：词数 ×10，慢的版本耗时约 ×100。

**为什么 `d` 就够了？** 因为 `d` 里的 keys 本来就等于「出现过的所有 key」，`seen` 装的是同一批东西——重复信息。判断某个 key 有没有出现过，问 `d` 就行。

### 坑 2：计数表的位置和类型

错误版本是把计数表建在循环**外**、且用 dict：

```python
counts = {}                     # ❌ 两重问题
for s in strs:
    for ch in s:
        counts[ord(ch) - ord('a')] += 1
```

- **问题 A**：空 dict 上 `counts[4] += 1` → `KeyError: 4`（没有的东西不能 `+1`）；
- **问题 B**：计数表没**每个词重置** → 计数跨词累加。实测 `["eat","tea","ate"]` 被拆成 **3 组**（本该 1 组），因为第二个词的 key 把第一个词的计数也带上了；
- **问题 C**（最隐蔽）：`tuple(counts)` 取的是 **dict 的键**，不是值！

  ```python
  counts = {4: 1, 0: 1, 19: 1}      # 'eat' 的 字母下标 → 次数
  tuple(counts)   # -> (4, 0, 19)   ← 次数全被丢掉，只剩「出现过哪些字母」
  ```

  这样的 key 退化成「排序过的字母种类」，实测会把 `"aab"` 和 `"abb"` 分到一组、把 `"ate"` 和 `"tan"` 分到一组。

**正确形态**：长度固定 26、有初值、**在每个词的循环体内新建**：

```python
for s in strs:
    counts = [0] * 26                    # 每个词一张全新的表
    for ch in s:
        counts[ord(ch) - ord('a')] += 1  # 'a'→0 … 'z'→25
    key = tuple(counts)                  # 26 个数字，长度固定 → 位置可比
```

## 四、两种解法对比（两版均已 AC）

| 解法 | key | 时间 | 说明 |
|---|---|---|---|
| 排序 | `tuple(sorted(s))` | O(n · k log k) | 思路最直观，先 AC 的版本 |
| 计数 | `tuple(26 个字母的计数)` | O(n · k) | 字母只有 26 种，无需排序；算 key 是 O(k) |

实测（n = 10⁴ 个词，本机 Python 3.12）：

| 单词长度 k | 排序当 key | 计数当 key |
|---|---|---|
| 10 | 0.004 s | 0.005 s |
| 100 | 0.046 s | **0.028 s** |

⚠️ 注意 k=10 时计数版反而**略慢**：它每词固定扫 26 格，k 小的时候这个固定开销比排序还贵。
数据量小就别为了「复杂度好看」过度优化 —— 但 k 大时 O(k) 的优势就出来了（k=100 快 1.6 倍）。

（n = 词数，k = 单词长度。空间都是 O(n · k)：dict 里存了 n 个词的引用，加上每个不同 key 本身长度 k。）
完整代码见 `solutions/0049-group-anagrams.py`（两个 class，都带注释）。

## 五、本题涉及的 Python 语法点

| 语法 | 要点 |
|---|---|
| `tuple(sorted(s))` | `sorted` 返回 **list**，list 可变 → 不能当 dict 的 key，转 tuple 才行 |
| `"".join(sorted(s))` | 同样可以当 key（str 也是不可变的），效果等价 |
| `d.values()` | ⚠️ 是 `values()` 不是 `value()`；返回的是 view，套 `list()` 才是题目要的返回类型 |
| `range(len(strs))` | `range` 后面必须带括号 |
| `strs[s]` vs `strs(s)` | `[]` 取元素，`()` 是调用函数（list 不能调用） |
| `ord(ch) - ord('a')` | 把 `'a'~'z'` 映射到 `0~25`，做计数表的固定下标 |
| `tuple(一个dict)` | 拿到的是 **keys**，不是 values —— 想连值一起拿要用 `tuple(d.items())` |

## 六、关键点 / 易错点

1. 哈希表解题的关键是 **key 设计**：同类算出的 key 必须完全相等，异类必须不同。
2. 「字母集合相同」≠ anagram，**次数**也必须相同。
3. `if key in d` 就够了，不要再用 list 记一遍 —— 那是把 O(1) 退回 O(n)。
4. dict 的 key 必须不可变；`list` 不行，`tuple` / `str` 可以。
5. 循环内的**临时状态**（计数表、路径、和）必须在每轮重新初始化，放到外面就会跨轮累加。
6. 返回类型要严格匹配函数签名：`list[list[str]]` ≠ `dict`。
7. 写完先拿**边界**试：`[""]`、`["a"]`、`["",""]`，再看性能。

## 七、347. Top K Frequent Elements（第二题）

### 1. 结构：两步走

| 步骤 | 做什么 | 代价 |
|---|---|---|
| 1 | 计数：`{数字: 出现次数}` | O(n) |
| 2 | 把 `d.items()` 按**次数**降序排，取前 k 个的**数字** | O(m log m) |

m = 不同数字的个数（≤ n），总时间 **O(n + m log m)**，最坏 O(n log n)；空间 O(m)。

⚠️ **「接力用加，嵌套用乘」**：上面两步是接力关系 → 相加；只有「对每个数都再干一遍 m 的事」才是相乘。

### 2. AC 写法

```python
d = {}
for num in nums:
    d[num] = d.get(num, 0) + 1          # get 带默认值：没见过就按 0 算

sorted_nums = sorted(d.items(), key=lambda x: x[1], reverse=True)
return [l[0] for l in sorted_nums[:k]]  # 每个元素是 (数字, 次数)，取第 0 号
```

- `d.items()` 给你 `[(数字, 次数), ...]`；`lambda x: x[1]` 表示「按第 1 号（次数）比」——**第 0 号才是数字，别搞反**；
- 直接 `sorted(d.items())` 排的是**数字**而不是次数（自己跑一遍看结果）。

### 3. 本题踩的坑

1. **`print` ≠ `return`（最严重）**：判题系统是调用你的函数、拿**返回值**去比对，打印到屏幕的东西它看不见；漏 `return` 会得到 `Output: null`。
2. `d.keys[i]` → `TypeError: 'builtin_function_or_method' object is not subscriptable`：`keys` 是方法，要写 `d.keys()`。
3. 就算写成 `list(d.keys())[:k]` 也**不对**：dict 的 key 顺序是**插入顺序（第一次出现的顺序）**，与次数无关。实测 `nums=[1,2,2,3,3,3], k=1` 会返回 `[1]`，正确答案是 `[3]`。
4. `sorted(...)` **不改原对象**（原地排序是 `list.sort()`），返回值不接住就等于白算。
5. 去掉 `dict(...)` 包装后 `sorted_nums` 变成 list，就不能再 `.keys()` —— **变量换了类型，用法要跟着换**。
6. 不能把 dict 的 `get` 方法当属性覆盖：`d.get = set(nums)` → `AttributeError: 'dict' object attribute 'get' is read-only`。
7. 不要自己造「两张平行表」（`key = set(nums)` + `value = [0] * len(key)`）来模拟映射：Python 的 dict **本身就是映射**，直接 `d[num] = 次数`。

### 4. 计数的三种写法（实测结果都一样）

```python
# A. 预初始化
d = dict.fromkeys(set(nums), 0)
for num in nums:
    d[num] += 1

# B. 见过就 +1，没见过就建（和 49 题同一模式）
d = {}
for num in nums:
    if num in d:
        d[num] += 1
    else:
        d[num] = 1

# C. get 带默认值（最省行数，推荐）
d = {}
for num in nums:
    d[num] = d.get(num, 0) + 1
```

### 5. Follow-up：优于 O(n log n)

| 版本 | 复杂度 | 空间 | 关键 |
|---|---|---|---|
| 计数 + 全排序 | O(n + m log m) | O(m) | `sorted(d.items(), key=lambda x: x[1], reverse=True)` |
| 计数 + 堆 | O(n + m log k) | O(m + k) | `heapq.nlargest(k, d.items(), key=lambda x: x[1])` |
| 计数 + 桶 | O(n) | O(n + m) | 用「出现次数」当桶的**下标**（次数 ≤ n） |

```python
# 桶版：时间 O(n)，靠「下标天然有序」省掉比较
d = {}
for num in nums:
    d[num] = d.get(num, 0) + 1

bucket = [[] for _ in range(len(nums) + 1)]   # 下标 = 出现次数，范围 0..n
for num, freq in d.items():
    bucket[freq].append(num)

res = []
for i in range(len(bucket) - 1, 0, -1):       # 从次数最大的桶往下扫
    res.extend(bucket[i])
    if len(res) >= k:
        break
return res[:k]
```

⚠️ **`bucket = [[]] * (len(nums) + 1)` 是错的**：这行只建了 **1 个** list，`*` 复制的是**引用**。
实测 `[[]] * 4` 之后往一格 append，四格全变成 `[['A'], ['A'], ['A'], ['A']]`。
**可变对象（list / dict / set）不能这样复制**，要用 `[[] for _ in range(n + 1)]`。

**同一组数据（n = 10⁵）实测耗时，ms，3 次取最好：**

| 场景 | 排序 | 堆 | 桶 |
|---|---|---|---|
| m ≈ n，k=10 | 6.97 | **4.87** | 10.42 |
| m ≈ n，k=1000 | 7.07 | **4.86** | 9.80 |
| m ≈ n，k=50000 | **7.37** | 14.57 | 9.89 |
| m = 100，k=10 | **2.13** | 2.15 | 8.50 |

**结论（比复杂度本身更值钱）**：

- k **很小**时用堆（O(m log k)，k=10 只要 4.87 ms）；
- k **接近 m** 时全排序反而更快（堆的 log k 变大了，维持大小为 k 的堆不划算）；
- 桶在理论上是 O(n) 最优，但**常数很大**（要开 n+1 个空 list），m 小时被另外两版吊打；
- **复杂度更优 ≠ 跑得更快**。选哪个取决于 k 与 m 的关系，以及能不能接受额外空间。
