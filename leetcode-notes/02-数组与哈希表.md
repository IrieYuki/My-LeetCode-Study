# 数组 & 哈希表（Array & Hashing）

> 专题笔记（路线图阶段 1）。来源：LeetCode 49（Group Anagrams）。
> 本文里的耗时数据均为本机 Python 3.12 实测，不是估计值。

## 一、一句话本质

**用 `dict` / `set` 把「查一个东西在不在」从 O(n) 降到平均 O(1) —— 拿空间换时间。**

哈希表能成立的前提：key 必须**不可变（hashable）**、且「查询用的东西」和「存储用的 key」是同一个。

---

## 二、核心问题：怎么设计 key

哈希表题目的难点从来不是「用不用哈希表」，而是 **key 长什么样**。判断标准：

> 题目说「两个东西算同一类」时，它们**若真的同一类，算出来的 key 必须完全相等**；若不同类，key 必须不同。

49 题的推导过程（费曼式自问自答）：

| 问题 | 答案 |
|---|---|
| anagram 之间差什么？ | **只有字母顺序** |
| 那顺序是干扰项吗？ | 是 → 把顺序抹掉 |
| 怎么抹掉？ | 排序（`sorted`），或干脆不记录顺序（计数表） |
| key 用什么类型？ | `tuple(sorted(s))` / `tuple(计数表)`，**list 不能当 key** |

⚠️ **最容易错的判据**：以为「字母集合相同」就算 anagram。

```
"aab" 和 "abb" 的字母集合都是 {a, b} —— 但它们不是 anagram！
因为 a/b 的【出现次数】不同。
```

所以 key 必须同时包含「有哪些字母」和「各出现几次」。`set(s)` 单独用一定错。

---

## 三、两个实测踩坑

### 坑 1：多维护一个 `seen` 列表来记 key

```python
seen = []                       # ❌ 多余
for s in strs:
    key = tuple(sorted(s))
    if key in seen:             # list 线性查找
        d[key].append(s)
    else:
        seen.append(key)
        d[key] = [s]
```

| 写法 | 10⁴ 个词的实测耗时 |
|---|---|
| `if key in seen`（list 线性查） | **0.449 s** |
| `if key in d`（dict 哈希查） | **0.004 s** |

**121 倍**，而且 `seen` 是平方级增长：词数 ×10，慢的版本耗时约 ×100。

**为什么 `d` 就够了？** 因为 `d` 里的 keys 本来就等于「出现过的所有 key」，`seen` 装的是同一批东西——重复信息。判断某个 key 有没有出现过，问 `d` 就行。

### 坑 2：计数表的位置和类型

错误版本是把计数表建在循环**外**、且用 dict：

```python
counts = {}                     # ❌ 两重问题
for s in strs:
    for ch in s:
        counts[ord(ch) - ord('a')] += 1
```

- **问题 A**：空 dict 上 `counts[4] += 1` → `KeyError: 4`（没有的东西不能 `+1`）；
- **问题 B**：计数表没**每个词重置** → 计数跨词累加。实测 `["eat","tea","ate"]` 被拆成 **3 组**（本该 1 组），因为第二个词的 key 把第一个词的计数也带上了；
- **问题 C**（最隐蔽）：`tuple(counts)` 取的是 **dict 的键**，不是值！

  ```python
  counts = {4: 1, 0: 1, 19: 1}      # 'eat' 的 字母下标 → 次数
  tuple(counts)   # -> (4, 0, 19)   ← 次数全被丢掉，只剩「出现过哪些字母」
  ```

  这样的 key 退化成「排序过的字母种类」，实测会把 `"aab"` 和 `"abb"` 分到一组、把 `"ate"` 和 `"tan"` 分到一组。

**正确形态**：长度固定 26、有初值、**在每个词的循环体内新建**：

```python
for s in strs:
    counts = [0] * 26                    # 每个词一张全新的表
    for ch in s:
        counts[ord(ch) - ord('a')] += 1  # 'a'→0 … 'z'→25
    key = tuple(counts)                  # 26 个数字，长度固定 → 位置可比
```

## 四、两种解法对比

| 解法 | key | 时间 | 说明 |
|---|---|---|---|
| 排序 | `tuple(sorted(s))` | O(n · k log k) | 思路最直观，AC 版本 |
| 计数 | `tuple(26 个字母的计数)` | O(n · k) | 字母只有 26 种，无需排序 |

（n = 词数，k = 单词长度。空间都是 O(n · k)：dict 里存了 n 个词的引用，加上每个不同 key 本身长度 k。）

---

## 五、本题涉及的 Python 语法点

| 语法 | 要点 |
|---|---|
| `tuple(sorted(s))` | `sorted` 返回 **list**，list 可变 → 不能当 dict 的 key，转 tuple 才行 |
| `"".join(sorted(s))` | 同样可以当 key（str 也是不可变的），效果等价 |
| `d.values()` | ⚠️ 是 `values()` 不是 `value()`；返回的是 view，套 `list()` 才是题目要的返回类型 |
| `range(len(strs))` | `range` 后面必须带括号 |
| `strs[s]` vs `strs(s)` | `[]` 取元素，`()` 是调用函数（list 不能调用） |
| `ord(ch) - ord('a')` | 把 `'a'~'z'` 映射到 `0~25`，做计数表的固定下标 |
| `tuple(一个dict)` | 拿到的是 **keys**，不是 values —— 想连值一起拿要用 `tuple(d.items())` |

## 六、关键点 / 易错点

1. 哈希表解题的关键是 **key 设计**：同类算出的 key 必须完全相等，异类必须不同。
2. 「字母集合相同」≠ anagram，**次数**也必须相同。
3. `if key in d` 就够了，不要再用 list 记一遍 —— 那是把 O(1) 退回 O(n)。
4. dict 的 key 必须不可变；`list` 不行，`tuple` / `str` 可以。
5. 循环内的**临时状态**（计数表、路径、和）必须在每轮重新初始化，放到外面就会跨轮累加。
6. 返回类型要严格匹配函数签名：`list[list[str]]` ≠ `dict`。
7. 写完先拿**边界**试：`[""]`、`["a"]`、`["",""]`，再看性能。
